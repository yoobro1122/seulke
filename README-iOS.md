# 슬케줄러 iOS — 포팅 브리프

이 문서는 안드로이드 버전(Kotlin + Jetpack Compose, `com.growv.seulkeduler`)을 iOS로
**완전히 새로 네이티브(Swift + SwiftUI)로 작성**하기 위한 브리프입니다. 목표는 별도
MVP가 아니라 **안드로이드 버전과 기능적으로 동일한 전체 기능**을 iOS에 구현하는 것입니다.
코드 공유(Kotlin Multiplatform 등)는 하지 않고, 언어/프레임워크만 iOS 관용적인 방식으로
바꿔서 전부 새로 짭니다.

## 아키텍처 결정

- **언어/UI**: Swift + SwiftUI
- **아키텍처 패턴**: MVVM (안드로이드의 ViewModel 패턴과 개념적으로 동일)
- **로컬 저장소**: SwiftData(iOS 17+ 권장) — Room처럼 선언적 모델링과 버전드 마이그레이션을
  지원해서 `Project`/`Task`/`ScheduleBlock`/`CheckinReview` 등 기존 Room 엔티티를 구조
  그대로 옮기기 쉬움. 더 낮은 iOS 버전까지 지원해야 하면 Core Data가 대안.
- **최소 지원 버전**: iOS 17 권장(SwiftData 기준). 더 넓은 기기 커버리지가 필요하면
  iOS 15+ + Core Data 조합도 가능.
- **위젯**: WidgetKit + SwiftUI(TimelineProvider) — Glance와 개념적으로 가장 가까움.
- **알림**: UNUserNotificationCenter 기반 로컬 알림 — AlarmManager+BroadcastReceiver+
  BootReceiver 조합이 하던 일(재부팅 생존)을 iOS가 자동으로 처리해줘서 오히려 더 단순해짐.
- **테마 시스템**: `LocalSeulColors`/`paletteFor(hue)` 구조는 SwiftUI Environment 값으로
  개념 그대로 이식 가능 — `Color(hue:saturation:brightness:)`로 HSL 계산도 더 간단해짐.

## 이식해야 하는 기능 전체 목록

안드로이드 버전에 실제로 구현되어 있는 기능입니다. 전부 동일하게 동작해야 합니다.

### 기본 골격
- 하단 탭 3개: **오늘 / 할일 / 설정** (통계 탭은 사용자 요청으로 애초에 범위 제외됨 — 없음)
- 오늘 탭의 3단계 바텀시트(peek/half/full), full일 때 하단 탭바를 시각적으로 덮음
- 세로 전용 화면 회전 고정

### 오늘 탭
- 날짜 이동, 24시간 타임라인(오늘이면 지금 시각 라인 포함)
- **목록 / 원형(다이얼) / 달력** 3가지 뷰 전환
  - 원형 뷰: 24시간 도넛형 두꺼운 호로 블록 표시, 오늘이면 중앙에 현재 시각 + "지금" 라인.
    읽기 전용(드래그/추가 없음)
  - 달력 뷰: 월 단위 이동, 요일 헤더는 "주 시작 요일" 설정을 따름, 스케줄 있는 날짜엔 점 표시,
    날짜 탭하면 목록 뷰로 전환
- 설정에서 오늘 탭 기본 화면(목록/원형)을 고를 수 있음, 앱 시작 시 딱 한 번만 반영
- 목록 뷰 진입 시 오늘 날짜면 현재 시각이 화면 위 1/5 지점에 오도록 자동 스크롤

### 타임라인 인터랙션
- 블록 드래그(몸통=이동, 하단 그립=리사이즈), 15분 그리드 스냅
- 자석 스냅(20분 이내면 다른 블록 가장자리에 딱 붙음)
- 인접 블록 자동 병합(같은 할 일끼리만)
- 빈 슬롯에 할 일 카드 롱프레스 드래그로 30분 블록 생성(고스트 미리보기)
- 빈 시간대 롱프레스 → "이벤트 선택" 모달(프로젝트별 미완료 할 일 중 골라 즉시 배치,
  맨 위 "+ 새 이벤트 추가"로 전체 폼도 열 수 있음)
- 블록 우상단 "×"로 스케줄에서만 삭제(할 일 자체는 안 지워짐)
- 일정 톤온톤 색상: 할 일 ID 해시로 프리셋 스와치 중 하나 고정 배정
- 리사이즈 그립 등 터치 영역은 44pt 기준으로 넉넉하게(보이는 크기는 그대로, 히트 영역만 확대)

### 할 일 탭 + 폼
- 프로젝트별 아코디언 + 완료됨 섹션
- 할 일 추가/수정 전체 화면 폼: 제목/프로젝트/타입(한 번·반복 — 반복이면 빈도+목표 횟수)/
  중요도(별 5개)/메모/링크/연결 앱
- 기존 카드 탭하면 같은 폼이 채워져서 열림, 삭제는 2단계 확인("삭제" → "정말 삭제?")

### 반복 설정
- 매일/매주[오늘 요일]/매월[특정 일자·마지막 날·N번째 요일] — 앱 전체에 활성화된 규칙은
  **단 하나만** 존재(새로 설정하면 이전 규칙을 완전히 덮어씀)
- 설정 완료 시 문장으로 요약("오늘 일정을 매월 넷째 주 수요일 반복합니다.") 후 확인 다이얼로그
- 확정 시점 타임라인이 템플릿 스냅샷으로 저장되고, 이후 "한 번도 열어본 적 없는" 오늘/미래
  날짜를 열 때 자동으로 채워짐(과거 날짜는 자동 채움 대상 아님)

### 체크인 + 진행 현황
- 체크인 모달: 블록 종료 시각이 지나면 자동 팝업("완료하셨나요?"), 60초 폴링으로 감지
- "완료" → 반복 할 일은 횟수 +1, 한 번 할 일은 완료 처리 / "못했어요" → 블록만 정리, 할 일은
  미완료로 남음. 한 줄 메모 입력 가능. 뒤로가기로 안 닫힘, 두 버튼 중 하나 눌러야 닫힘
- 완료/못했어요 확정 시 짧은 리액션 애니메이션(성공=오버슈트 바운스+컨페티, 실패=톤다운된
  처짐-복귀) — 안드로이드는 Lottie(bodymovin JSON) 사용, 재생 끝나는 시점에 맞춰 모달 자동 닫힘
- **진행 현황 요약 (RECURRING 전용)**: 할 일 상세뷰에 가로 바 그래프로 표시
  - 목표가 있고 `목표+미완료 ≤ 12`면 시도 순서대로 채운 세그먼트 칸 바(완료색/미완료색 구분 +
    목표까지 남은 칸은 점선 테두리), 12 초과거나 무제한이면 완료:미완료:남음 비율의 연속형 바
  - 헤더에 "N/목표 완료"(또는 무제한이면 "누적 N회") 알약 태그만, 숫자 범례 없음
  - 완료 칸=accent, 미완료 칸=inkFaint(desaturated), 남은 칸=점선 아웃라인만(고정 hex 없음,
    테마 바뀌면 같이 바뀜)
- **목표 기반 종료 로직**: "n회 반복"의 n = 완료해야 하는 횟수. 미완료는 n에 안 들어가고
  다음 회차가 자동으로 하나 더 생김. 완료 횟수가 n에 도달하면 그 즉시 조용히 종료. 시도
  횟수가 먼저 n에 도달했는데 아직 목표를 못 채웠으면 "N회 완료될 때까지 계속할까요?" 확인
  모달이 **정확히 한 번**만 뜸 — "네"면 다시 안 묻고 목표까지 계속, "아니요"면 그 자리에서 종료
  (이미 미리 채워져 있던 미래 블록도 함께 정리)
- 할 일 상세뷰 "최근 리뷰 목록": 최신순 5개(날짜·완료여부·메모·회차)
- 과거 일정 블록 탭 → 그날의 리뷰 보기: 블록 상세 모달에 "그날의 기록" 섹션(있으면), 리뷰
  달린 블록은 목록 뷰에 작은 점 표시

### 테마 / 폰트 / 아이콘
- 색상 테마: hue 하나로 bg/ink/accent/스와치 등 전부 자동 유도(`paletteForHue`). 기본
  내장 4개(모노톤 화이트/딥퍼플/타이탄/포레스트 그린) + hue 슬라이더로 커스텀 테마 무제한
  생성/수정/삭제 가능(모노톤 화이트만 삭제 불가). 스와치 7개 중 원하는 칸만 개별 hue로
  오버라이드 가능. 테마 이름은 UI 어디에도 표시 안 함(스와치 미리보기만으로 선택)
- 폰트: Playfair Display(제목, SemiBold) / Inter(본문, Regular·Medium) / IBM Plex Mono(작은
  라벨/숫자). 전부 실제 폰트 파일 번들링(플레이스홀더 아님)
- 아이콘: Material Symbols Rounded 계열(각진 Filled 아님, 전부 둥근 스타일) — iOS에서는
  SF Symbols로 대체할지 동일 아이콘셋을 직접 번들할지 결정 필요
- 코너 반경 토큰(pill/small 14dp/medium 22dp/large 28dp/scheduleBlock 균일 18dp)을 앱
  전체 다이얼로그/버튼/블록에 일관 적용
- 톤온톤 그라데이션(스케줄 블록, 하단 탭 활성 필, "완료했어요" 버튼): 테마의 accent/스와치
  색에서 매번 계산되는 밝은 변형(고정 hex 없음)

### 위젯
- 홈 화면 2x2 원형 다이얼 위젯: 상단 현재 시각, 가운데 오늘 일정 도넛형 다이얼, 하단
  지금/다음 일정 제목. 탭하면 앱 열림
- 색상 테마(커스텀 포함) 위젯에도 반영, 테마 바뀌면 즉시 다시 그려짐
- (플랫폼 차이 — 아래 참고) 안드로이드는 분 단위 실시간 갱신이지만 iOS 위젯 새로고침
  예산 제약으로 동일 수준은 어려움

### 알림 / 햅틱
- 일정 시작 시각에 OS 알림, 앱이 꺼져 있어도 옴
- 중요도(별 1~5)별 알림 스케줄 고정표: 1~2개=알림 없음, 3개=시작 시 1번, 4개=10분 전+시작 시
  2번, 5개=30분 전+10분 전+시작 시 3번. 메시지 톤도 5단계로 다름
- 확정/삭제류 액션(체크인 완료/못했어요, 블록 삭제, 반복설정 확인, 할 일 삭제 확인)에만
  짧은 햅틱, 이동/토글 같은 가벼운 탭에는 없음. 설정에서 햅틱 켜기/끄기 가능

### 설정 탭
- 오늘 탭 기본 화면(목록/원형), 주 시작 요일(일/월), 일정 시작 알림 켜기/끄기, 햅틱
  켜기/끄기, 색상 테마, 데이터 초기화, 백업/복원(JSON 내보내기/가져오기)
- 계정/로그인 항목 없음(서버·로그인 없는 순수 로컬 앱)

### 할 일 ↔ 앱 연결 (플랫폼 차이 있음, 아래 참고)
- 할 일에 기기의 설치된 앱을 하나 연결(아이콘+이름), 폼에 칩으로 표시, "×"로 해제 가능

## iOS 플랫폼 제약으로 그대로 못 옮기는 것 (재설계 필요)

1. **앱 연결 기능** — 안드로이드는 `PackageManager`로 설치 앱 목록+아이콘을 직접 조회하지만,
   iOS는 샌드박스 정책상 설치 앱 목록 조회 자체가 불가능한 API 자체가 없음. 대신 `canOpenURL`로
   확인 가능한 특정 URL 스킴을 미리 등록해두는 방식으로만 대체 가능 — UX 자체를 다시 설계해야 함.
2. **위젯 실시간 갱신** — 안드로이드는 분 단위(`ACTION_TIME_TICK`)로 위젯이 갱신되지만, iOS
   위젯(WidgetKit)은 하루 새로고침 횟수 자체에 시스템 예산 제한이 있어서 같은 수준의 실시간성은
   못 냄. 완전히 동일한 "실시간" 느낌은 기대하지 말 것.

## 단계별 로드맵

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1. 프로젝트 골격 | Xcode 프로젝트 생성, SwiftData 모델(Project/Task/ScheduleBlock) 이식, 하단 탭 3개(오늘/할일/설정) 뼈대 | 앱이 실행되고 탭 전환이 된다 |
| 2. 오늘 탭 타임라인 | 목록 뷰 블록 표시, 드래그/리사이즈/자석스냅/자동병합 | 블록 배치·이동·삭제가 Android와 동일하게 동작 |
| 3. 원형/달력 뷰 | Canvas 기반 다이얼, 달력 그리드, 뷰 전환 | 세 뷰 모두 전환 가능 |
| 4. 할 일 탭+폼 | 프로젝트/할일 CRUD, 전체 폼 화면 | 할 일 생성/수정/삭제 가능 |
| 5. 반복설정+체크인+진행현황 통계 | RecurringRule 이식, 체크인 모달, CheckinReview, 진행률 바, 목표 기반 종료 로직 | 반복 일정 자동 채움 + 체크인 기록 + 그래프 표시 + 목표 달성 시 자동 종료 |
| 6. 테마/폰트/아이콘 | SeulColorScheme 이식, 폰트 번들, 아이콘셋 결정, 코너 반경 토큰, 톤온톤 그라데이션 | 테마 전환 및 커스텀 테마 동작 |
| 7. 알림+햅틱 | UNUserNotificationCenter, 중요도별 스케줄, 햅틱 | 권한 요청 흐름 + 실제 알림 수신 확인 |
| 8. 위젯+백업/복원 | WidgetKit, UIDocumentPickerViewController | 위젯 갱신, 백업 JSON export/import 확인 |
| 9. 앱 연결 기능 재설계+마무리 | iOS 대안 설계, 접근성(44pt) 점검, 실기기 QA | 전체 기능 실기기 확인 완료 |

## 데이터 모델 참고

안드로이드 버전 `app/src/main/java/com/growv/seulkeduler/data/`의 `Project`/`Task`/
`ScheduleBlock`/`CheckinReview`/`AppSettings`/`CustomColorTheme` 엔티티 구조를 필드
단위로 그대로 따라가면 됩니다. 주요 필드:

- `Task`: 제목/프로젝트/타입(ONCE/RECURRING)/빈도/목표 횟수(`target`)/진행(`count`)/
  완료(`done`)/중요도(1~5)/메모/링크/연결앱 패키지명/`recurringEnded`/
  `recurringGoalPromptAnswered`
- `ScheduleBlock`: taskId/날짜/시작시각/길이/`checkinPending`/`state`(LOGGED 등)
- `CheckinReview`: taskId/blockId(참고용)/완료여부/메모/그 시점 반복 회차 스냅샷
- `AppSettings`: 싱글턴 설정 행(오늘 탭 기본 화면, 주 시작 요일, 알림/햅틱 켜기끄기,
  colorTheme, recurringTemplate* 등)
- `CustomColorTheme`: `baseHue` + `presetHueOverrides`(스와치별 개별 hue, nullable)
